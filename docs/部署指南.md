# 部署指南 Deployment

本仓库为 monorepo：前端在 `web/`（Vite SPA），可选后端在 `server/`。前端默认 Local-First，**不部署后端也能完整使用**。

---

## 方式一：Vercel（推荐）

最简单的前端托管，push 即自动部署，SPA 刷新不会 404。

1. 打开 https://vercel.com/new ，选择 **Import Git Repository**，授权并选择 `xiaomutou-git/ShoreOps`。
2. 关键：**Project Root Directory 选择 `web`**（因为是 monorepo）。
3. Framework Preset 会自动识别为 **Vue**；其余构建配置已在 `web/vercel.json` 中：
   - Build Command：`pnpm build`
   - Output Directory：`dist`
   - SPA 回退：所有路由重写到 `index.html`
4. 点击 **Deploy**。完成后得到 `https://<your-project>.vercel.app`。
5. 之后每次 push 到 `main` 都会自动重新部署。

> 如需在线使用后端，可在 Vercel 的 Environment Variables 中配置后端地址，并在前端用环境变量引用（Vite 中以 `VITE_` 前缀暴露）。

---

## 方式二：GitHub Pages（仅前端静态托管）

地址形如 `https://xiaomutou-git.github.io/ShoreOps/`。

GitHub Pages 在子路径托管，且服务器没有 SPA 回退，需要两处代码适配：

1. **Vite base**：在 `web/vite.config.ts` 顶层设置 `base: '/ShoreOps/'`。
2. **路由改为 hash 模式**：把 `createWebHistory()` 改为 `createWebHashHistory('/ShoreOps/')`，以避免刷新内页 404。

完成上述改动后，可使用 `.github/workflows/deploy-pages.yml`（如需可提供）在 push 时自动构建并发布到 GitHub Pages。

> 注意：`base` 与 hash 路由会影响本地开发与 Vercel 路径，**确定使用 Pages 再改**；若用 Vercel 则保持现状即可。

---

## 方式三：后端部署（可选）

`server/` 是 Node.js 服务，可部署到任何支持 Node 的平台（Render / Railway / 自有服务器）。

- 生产环境必须设置环境变量：
  - `NODE_ENV=production`
  - `JWT_SECRET`：至少 32 位随机字符串
  - `CORS_ORIGIN`：你的前端正式域名（白名单）
  - `PORT`、`DB_PATH`
- 零知识架构：服务端只存储密文与 nonce，无法解密用户数据。
