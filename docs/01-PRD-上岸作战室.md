# 上岸作战室（ShoreOps）产品需求文档（PRD）

- 文档版本：V1.0
- 文档状态：评审稿
- 产品代号：ShoreOps
- 适用读者：UI 设计师、前端工程师、后端工程师、测试、运营
- 技术总原则：Local-First（本地优先）、可离线使用、隐私不出设备

## 1. 产品概述

### 1.1 产品名称

**上岸作战室**（英文名 ShoreOps，Slogan："目标日倒排，每一天都朝着 Offer 开火"）。

产品以"抢滩登陆作战"为统一视觉与语言隐喻：

- 拿到 Offer = 成功登陆上岸
- 目标 Offer 日期 = D-Day（登陆日）
- 倒排出来的关键节点 = 里程碑（Milestones）
- 每日行动 = 作战任务
- 申请进展 = 战场态势（漏斗看板）
- 心态精力 = 士气能量
- 面试题/话术/简历素材 = 知识弹药

### 1.2 一句话定位

一款以"上岸日倒排作战规划"为核心、把求职全过程（计划—执行—投递—复盘—心态）统管起来的**求职指挥中枢**：输入目标日期，自动生成里程碑、周计划与每日任务，并持续管理申请漏斗与士气能量。

### 1.3 产品愿景

让每一个求职者从"焦虑地海投、被动地等待"，变成"有登陆日、有作战图、有每日任务、有弹药补给、有战报复盘"的指挥官——**在确定的节奏里，拿到确定的 Offer**。

### 1.4 产品形态

- 形态：响应式 Web 应用（PWA），优先移动端浏览器可"添加到主屏幕"，桌面端为高效工作台。
- 数据：默认 100% 存储在用户本地设备（IndexedDB + LocalStorage），无账号、无后端也能用；离线可完整使用。
- 商业化预留：V1.x 不做付费；V2.0 可选端到端加密云同步（增值）。

## 2. 市场与机会分析

### 2.1 市场背景

- 求职人群规模庞大且周期性强：每年校招应届生超 1100 万，叠加社招跳槽、被裁再就业、跨行业转行人群，"求职"是高频高焦虑刚需。
- 求职行为天然是"多工具、长周期、强目标日期"的项目：准备简历→投递→笔试→多轮面试→谈薪→决策，通常持续 1–6 个月。
- TRAE 论坛现有作品已覆盖 13+ 个**单点工具**，但全部停留在"解决某一个动作"，缺少一个把它们**按时间轴编排成一场战役**的中枢层。这正是本品的空白机会。

### 2.2 目标用户画像

#### 画像 A：校招生（时间驱动型）—— 小林

- 22 岁，应届硕士，无全职经验。
- 强外部时间线：提前批（7–8 月）、正式批（9–10 月）、补录（11–12 月）、春招（次年 3–4 月）。
- 痛点：不知道现在该干什么、错过批次节点、海投无记录、同辈焦虑、笔试面试扎堆撞车。
- 核心诉求：**按官方批次倒排的时间表 + 多公司进度不混乱 + 焦虑时被工具托底**。
- 使用环境：手机为主，宿舍/通勤/深夜，碎片化高频。

#### 画像 B：社招在职者（隐蔽作战型）—— Amy

- 28 岁，在职，想 2–3 个月内跳槽，薪资期望涨幅 20–30%。
- 痛点：只能利用早晚和周末、面试要请假协调、多家公司阶段并行容易忘、怕被现公司发现、决策期要横向对比 Offer。
- 核心诉求：**隐私绝对安全 + 碎片时间执行当日任务 + 多公司漏斗一目了然 + 面试/谈薪复盘**。
- 使用环境：桌面端为主（晚上在家），手机查看与快速打卡。

#### 画像 C：转行者（能力重建型）—— 老周

- 32 岁，传统行业转互联网，准备期更长（3–6 个月）。
- 痛点：目标岗位认知模糊、旧经历不会"翻译"成新岗位语言、缺少知识体系、容易自我怀疑中途放弃。
- 核心诉求：**更长准备期的倒排里程碑 + 话术与简历素材持续沉淀 + 心态续航**。
- 使用环境：学习时间大块（周末）+ 小块（平日晚上）混合。

### 2.3 用户核心痛点

| 编号 | 痛点 | 现状替代方案 | 现状方案的缺陷 |
|---|---|---|---|
| P1 | 没有全局时间表，不知道"今天/这周该干什么" | Excel、备忘录 | 不会自动倒排、没有节奏、容易拖延 |
| P2 | 投了几十家，进度和时间线混乱 | 招聘 App、Excel | 不聚合多平台、无停留预警、无转化率 |
| P3 | 心态崩、焦虑内耗，坚持不下去 | 找人倾诉 | 无人即时干预、情绪无记录、低谷期放弃 |
| P4 | 面经、错题、话术散落各处 | 文档、收藏、截图 | 用时找不到、不复用、不沉淀 |
| P5 | 面完不复盘，同类问题反复错 | 偶尔写笔记 | 无结构化模板、无数据反馈闭环 |
| P6 | 敏感求职数据有泄露顾虑 | 在线文档/登录工具 | 数据上云、担心被看到 |

### 2.4 与现有单点工具的差异

| 维度 | 现有单点工具 | 上岸作战室 |
|---|---|---|
| 核心问题 | 把某一个动作做好 | 把"拿到 Offer"终极目标倒排并推进到完成 |
| 时间结构 | 无时间轴或弱时间轴 | 以 D-Day 为锚的里程碑→周→日三级倒排 |
| 工具关系 | 互相独立，数据不通 | 中枢调度：漏斗事件生成任务、面试生成复盘 |
| 心态管理 | 基本不涉及 | 一级模块：能量记录、焦虑急救、成就激励 |
| 数据策略 | 多为云端、需登录 | 本地优先、离线可用、无需注册 |
| 用户体感 | "用一次的工具" | "每天打开的作战指挥台" |

### 2.5 核心价值主张

1. **给确定感**：输入一个日期，得到一张可执行作战地图，把"我要找到工作"翻译成"今天做这三件事"。
2. **给掌控感**：一张看板掌握所有公司进度、停留预警与转化率。
3. **给续航力**：把士气与精力当作作战资源管理，低谷急救、进步正反馈。
4. **给安全感**：数据只存在于自己设备，离线全功能可用。
5. **给复利沉淀**：面过的题、练过的话术、攒下的素材全部本地沉淀，越用越强。

## 3. 核心功能模块

全局导航（移动端底部 Tab、桌面端左侧导航）：**指挥台 / 作战地图 / 任务 / 漏斗 / 弹药库 / 能量站 / 复盘室 / 我的**。移动端默认 5 Tab：指挥台、任务、漏斗、能量、我的。

### 3.1 模块一：上岸倒计时与倒排作战地图

- 指挥台顶部固定显示：`距 D-Day 还有 N 天`（大号数字）+ 目标岗位/城市 + 今日日期。
- 状态分支：未设目标（引导）、进行中、已过期未上岸（一键顺延 7/14/30 天）、已上岸（胜利态）。
- 进度条：已过天数 / 总战役天数，叠加里程碑标记。

**倒排规则（核心算法）**：输入求职类型、目标日期、目标岗位、每周可作战天数。内置三套里程碑模板（D-x = 目标日前 x 天）：

**社招模板（约 12 周）**

| 里程碑 | 默认时间 | 关键交付 |
|---|---|---|
| M0 战役启动·定位准备 | D-84 | 确定目标，完成简历 V1 |
| M1 弹药就位 | D-70 | 作品集/话术/3 个 STAR 故事定稿 |
| M2 投递启动 | D-63 | 30 家目标清单，首批投 10 家 |
| M3 笔试/初面期 | D-49 | 累计投递 ≥30 |
| M4 面试密集期 | D-28 | 每周 ≥3 场面试 |
| M5 Offer 收割与谈判 | D-14 | 拿到首个 Offer，启动谈薪 |
| M6 决策上岸 | D-Day | 对比 Offer 并确认接受 |

**校招模板**：节点绑定批次日历（网申窗口、笔试周）。**转行模板（约 16 周）**：M0 前增加岗位调研（D-112）、知识补课（D-98）、迁移经历翻译（D-84），投递后移至 D-56。

- 级联规则：移动里程碑可选仅移动/整体顺延；修改 D-Day 默认整体重算，历史永不删除。
- 视图：时间线视图（默认）、甘特视图（桌面端），阶段底色带贯通。
- 里程碑完成需关联任务完成率 ≥80% 或强制完成（二次确认）。

### 3.2 模块二：每日作战任务

- **今日三垒（MIT）**：3 个置顶坑位，来源为系统推荐/漏斗联动/手动添加；超出进入"今日其他任务"。
- 任务字段：标题、类型（投递/简历/刷题/面试/复盘/学习/人脉/休整）、优先级、预估时长、所属里程碑、关联公司/弹药、截止日期、重复规则、备注。
- 状态：待办→进行中→已完成，另设部分完成/跳过；支持打卡、编辑、删除、顺延（每日限 3 次）、转 .ics。
- **连续作战天数 Streak**：当天完成 ≥1 件即记 1 天；每周赠 1 张休整券防断签；断签不嘲讽，历史最长保留。
- **今日战报**：21:00 或收工时生成完成 X/Y、连签 N 天、文案，可本地 canvas 生成图片（默认脱敏）。

### 3.3 模块三：申请漏斗看板（轻量）

- 固定 6 列：**意向 → 已投递 → 笔试 → 面试 → Offer → 已结束**；面试列标注轮次；已结束需选原因；允许反向流转。
- 卡面：公司、职位、渠道、停留天数、薪资、优先级、预警色；详情含 JD、联系人、面试安排、附件、事件时间线。
- 看板拖拽换列，弹窗确认日期+备注，自动生成建议任务；移动端降级列表+筛选 Chips。
- **停留预警**：已投递 ≥5 天黄色/≥10 天红色；笔面后 ≥7 天黄色。
- **转化率**：各列在池数、阶段转化率（只统计终态）、平均响应/投递到 Offer 天数；样本不足提示。

### 3.4 模块四：士气能量站

- **每日能量记录**：能量值 1–5（电池视觉）+ 情绪标签 + 一句话日记，10 秒完成，可补记近 3 天。
- **能量曲线**：近 14/30 天折线 + 事件标记（面试/被拒/Offer），弱洞察描述。
- **焦虑急救箱**：478 呼吸引导、5 分钟身体扫描、焦虑三问（认知重评）、等待消音室、战报打气墙、一键休整（休整券）。
- **成就体系**：火力首投、精准制导、初次交火、登陆成功、七日不退、百日铁军、弹如雨下（投 50）、复盘狂人、绝地反击、低谷反弹；勋章墙 + 上岸胜利结算长图/PDF。

### 3.5 模块五：知识弹药库

- 分类：面试题库（掌握度+间隔重复 1/3/7/15 天）、错题本、话术卡（自我介绍/项目/转行原因/薪资/反问）、STAR 简历素材、公司情报。
- 全局标签、全文本地搜索、Markdown 编辑、今日待复习智能集合。
- 联动：任务关联弹药、复盘答砸题一键转错题、战备值统计。

### 3.6 模块六：复盘作战室

- **每日三问**：今天推进了什么？最大卡点？明天最重要一件事？（预填次日 MIT）。
- **面试复盘**：基础信息、题目清单（好/一般/砸）、五维评分、高光/短板/3 个改进动作、结果与归因。
- **数据洞察**：周报（投递/面试/完成率/作战天数/能量/弹药环比）、规则引擎瓶颈诊断（简历通过率低、笔试转化低、面试零 Offer 等），均带数据口径，样本不足不下结论。

### 3.7 模块七：个人中心与设置

- 求职档案、目标管理（改 D-Day/暂停/结束）、提醒设置、数据管理（本地总览/加密导出/导入/清空）、外观（深色默认/浅色、字号、减弱动效）、离线指示、隐私声明。

## 4. 关键用户场景

1. **小林秋招倒排与焦虑急救（校招）**：9/1 设定 D-Day=11/30，30 秒生成地图；10 月深夜低能量，478 呼吸+休整券早睡；11/28 接受 Offer，结算 88 天/47 投/9 面/12 勋章。
2. **Amy 多线并行碎片作战（社招在职）**：午休手机跟进停留 9 天公司、生成二面准备任务；地铁复习话术；面后 10 分钟复盘，错题入库；晚上桌面甘特排兵。
3. **老周转行续航弹药复利（转行）**：模板多出调研/补课/翻译里程碑；制造业经历写成 5 个 STAR；首面挂后专项突破错题，二面对答如流。
4. **被拒三连低谷反弹**：1 分能量+一键休整保住连签；收工三问定位群面短板；周报发现 6/12 死于薪资不符，校准期望，提前 9 天登陆。

## 5. 业务流程

主流程闭环：**首次进入与目标设定 → 倒排生成作战计划 → 每日执行与打卡 → 阶段复盘与动态调整 → 达成上岸与战役结算**（未达成则顺延—重排循环）。

核心规则：计划永远可改、历史永不丢失（事件流追加）；系统建议不强制；最小闭环（目标设定+每日打卡）即提供完整价值。

## 7. 数据模型（本地优先）

IndexedDB（Dexie 封装）+ LocalStorage；通用审计字段：`id(UUID)`、`createdAt`、`updatedAt`、`deletedAt(软删)`、`version`。

核心实体：UserProfile、Goal（含版本快照）、Milestone、Task、Application、StageEvent（只追加，时间线与转化率事实来源）、Interview、InterviewReview、DailyReview、MoodLog、KnowledgeItem、Tag、AchievementDef/UserAchievement、Settings、Attachment。

关系：Goal 1:N Milestone 1:N Task；Application 1:N StageEvent/Interview；Interview 1:1 InterviewReview；Task N:1 Application、N:M KnowledgeItem；复盘题目转 KnowledgeItem、动作转 Task；Tag N:M KnowledgeItem。

完整性：写操作走 Repository 事务（换列时 Application 更新与 StageEvent 追加原子）；schemaVersion 增量迁移；软删 30 天回收站。

## 8. 功能优先级（MoSCoW）

- **Must**：目标设定、三套倒排模板与任务摊排、里程碑级联、今日三垒与打卡 Streak、漏斗 6 阶段拖拽、能量记录、弹药库三类 CRUD、收工三问、IndexedDB+PWA 离线、档案与清空。
- **Should**：转化率与停留预警、面试复盘、焦虑急救箱、成就战报、间隔复习、周报诊断、加密导入导出、甘特图。
- **Could**：能量曲线洞察、PDF/长图、外部工具导入、.ics、多主题、公司情报、附件。
- **Won't**：社区/IM、云账号协作、自动抓取/投递/代聊、付费广告 B 端、在线 AI（V2.0 再评估本地模型/自带 Key）。

---

## 9. 非功能性需求

- **性能**：TTI ≤2s，Lighthouse ≥90，列表虚拟滚动，索引查询，拖拽响应 ≤100ms，5MB 预警。
- **安全隐私**：无后端无账号无埋点，业务数据零外发；敏感字段默认打码；AES-GCM 加密导出；HTTPS+CSP；禁用 eval/document.write；异步与 DOM 操作 try-catch；分享默认脱敏。
- **响应式**：断点 375–428/768/≥1280，下限 320；桌面侧导航+多列+甘特，移动底部 Tab+单列+列表降级，触控 ≥44px。
- **无障碍**：WCAG 2.1 AA，对比度 ≥4.5:1，状态不只靠颜色，键盘可达与拖拽替代，ARIA，减弱动效，字号调节。
- **可靠性**：配额异常保留输入，安全模式导出重建，schema 向前兼容。

## 10. 迭代路线图

- **V1.0 MVP（5–6 周）**：全部 Must have，跑通上岸闭环；验收：引导 ≤3 步 ≤1 分钟、断网全功能、清空无残留、Lighthouse 四科 ≥85。
- **V1.1（3–4 周）**：洞察与心态补给（Should 主体）+ 7 天示例数据。
- **V1.2**：PDF/导入/日历/多主题与专项打磨。
- **V2.0**：可选端到端加密同步、隐私友好 AI（本地模型/自带 Key）、模板生态。

## 11. 成功指标

- **北极星**：周作战活跃上岸率（每周 ≥3 天打卡者，在目标日起 14 天内标记上岸比例）；冷启动期以周作战活跃用户数为代理。
- **过程指标**：目标完成率 ≥70%、次日首打卡 ≥60%；次留 ≥55%/7 留 ≥35%/30 留 ≥20%；人均周作战 ≥3.5 天、三垒完成 ≥60%；人均在管 ≥10、周新增投递 ≥5；面后 24h 复盘 ≥50%；能量周覆盖 ≥60%；人均弹药 ≥15；导出成功率 ≥99%、0 数据外发、崩溃率 <0.5%。
- 指标通过本地面板 + 用户自愿匿名汇总获取，V2.0 授权后仅收集脱敏聚合数值。

## 附：落地要点

- 统一军事隐喻：深色作战地图+阶段色带+勋章，基调"有序、冷静、被托举"，避免真实攻击性元素。
- 三个核心体验：倒排 30 秒魔法时刻、打卡爽感与不断签容错、低能量被温和接住。
- 三条工程红线：业务数据零外发；异步/DOM 操作 try-catch；变更事件流追加、历史不删。
- 建议技术栈：Vue 3 + TypeScript + Vite（PWA）+ IndexedDB(Dexie) + WebCrypto + 响应式 CSS；可无后端交付，后端作为可选加密同步服务。
